# 使用 generate_image 生成或编辑图像

当用户想要生成、编辑、转换或迭代图像时，使用该技能。生成和编辑都用 `generate_image`；对于编辑或基于参考的生成，通过 `reference_images` 提供相关图像。

## 核心行为

- 在准备请求之前，先理解用户的视觉意图。
- 不要要求用户手动提供每一个生成参数。
- 尽可能推断合理的值。
- 只有当缺失信息会实质性改变结果时才追问。
- 用户显式给出的指令优先于推断出的默认值。
- 生成前，先概括解析后的请求，并请用户确认。
- 除非用户明确要求立即执行，否则在确认之前不要调用 `generate_image`。

## 参考图像

`reference_images` 可能来自：当前对话中的图像 / 用户上传的附件 / 先前生成的图像 / 用户明确引用的图像。

根据用户意图确定每张参考图像的角色：正在被编辑的图像 / 主体或内容参考 / 风格参考 / 构图参考。除非用户意图就是修改某张参考图像，否则不要把它当作编辑目标。用户明确指向一张可用图像时，直接用它，不要再要求用户指认一遍。存在多张候选图像、而目标或角色不明确时，在生成前询问。

## 提示词准备

把用户的请求转换成清晰的图像生成指令；用户不需要先写出正式提示词。保留用户明确要求的内容：主体 / 场景 / 风格 / 构图 / 光照 / 颜色 / 相机或视角 / 文字 / 重要的视觉约束。不要悄悄引入对用户预期的主体、含义或视觉方向的重大更改。

### 编辑

清楚区分"应当更改的内容"与"应当保持不变的内容"，默认保留不相关的内容。例如用户只要求改天空时，不要不必要地改动主体、身份、姿势、背景对象或构图。

## 参数

从用户请求中推断生成参数，而不是逐个追问。

### `n`

用户指定时用请求的数量；未指定时 `n = 1`；用户要求多个方案但没有指定数量时，选工具支持的一个较小的合理数量。

### `resolution`

支持的值（**示例，实际按该模型支持的值**）：`1K` / `2K` / `4K`。一般指导：快速预览或概念探索用低档，普通生成用中档，高细节或最终质量用高档。未指定时，用**该模型 schema 里的 `default`**。有帮助时告诉用户可选档位，而不是要求他们先选。

### `aspect_ratio`

取值以该模型 schema 为准。改图时除非用户指定，否则优先沿用原图比例（不支持时选最接近的支持比例，并尽量减少裁剪或扩展）；新图按预期用途或构图判断比例；推断不出来时用工具默认值。除非用户要求，不要悄悄把横向改成纵向，或实质性改变构图。

## 确认

调用 `generate_image` 前，简要总结解析后的任务：将生成或更改什么 / 参考图如何使用（适用时）/ `n` / `resolution` / `aspect_ratio`；编辑还要带上重要的保留约束。

示例（生成）：

> 将生成：黄昏时分海边的灯塔，2 张，2K，16:9。可调整为 1K/4K 或其他支持的比例，确认后生成。

示例（编辑）：

> 将修改：把天空换成星空；主体、姿势与构图保持不变。2K，优先按原图比例适配，确认后生成。

保持简洁；除非用户要求，不要展示完整的内部提示词。以下肯定回复视为执行授权：`确认` / `可以` / `生成` / `开始` / `就这样` / `按这个来`。用户改动请求时，更新并确认修订版；用户明确要求立即生成或跳过确认时，直接执行。

## 迭代

除非用户明确开始新任务，把后续请求视为当前任务的延续，复用 `reference_images`、当前编辑目标、视觉方向、保留约束与先前参数。示例：`再亮一点` / `背景简单一些` / `改成晚上` / `人物小一点` / `改成 16:9` / `再生成两个版本`。不要要求用户重复完整的请求；下一次实际生成前仍按确认规则。

## 工具使用

调用前视情况解析 prompt / `reference_images` / `n` / `resolution` / `aspect_ratio`。**以实际的 `generate_image` schema 为事实来源，不要发明不受支持的参数或枚举值。** 简而言之：理解 → 推断 → 确认 → 生成。
