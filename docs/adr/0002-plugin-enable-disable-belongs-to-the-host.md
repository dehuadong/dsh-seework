# 插件的启停归宿主，插件不自带总开关

- 状态：实现完成（2026-09-30）
- 日期：2026-09-30
- 相关：Agent Note [设置卡片：退役「启用插件」、把「保存」留给它真正保存的那一节](../../.agents/notes/implemented/canvas/2026-09-30-settings-switches-and-save.md)、工作项 `dehuadong/dsh-seework#5`

插件的启停由宿主的插件管理拥有，插件自己的设置文档里不再有总开关。本决定说明这条归属、它换来了什么，以及被否决的几种做法。

## 背景

宿主的插件管理拥有插件的启停：`plugin_manager` 的 `setPluginEnabled`，以及 profile 里的 `disabled`。停用即整个插件不加载。

插件自己的设置文档里另有一个 `enabled`，它管四处：系统提示词公告、随包技能是否注册进宿主的技能目录、Agent 工具调用时拒绝（`plugin-disabled`）、生成路由拒绝（`plugin-disabled`）。它让代码在位却不干活，与宿主那个开关对同一件事各有一套做法。

对 Agent 而言这两个开关语义相同：`enabled=false` 时 Agent 同样生不了图，而"允许 Agent 生图"就是这件事本身。用户实测的结论是这两个勾选应当合并。

## 决定

1. **插件不自带总开关。** 启停归宿主的插件管理。
2. **`allowAgentGeneration` 是插件内唯一的行为开关。** 它决定 Agent 能否调用 `generate_image`；用户自己在面板里生图不受它影响。
3. **退役的 `enabled` 不被读取**，并且仍带着它的设置文档会被清掉：每次启动检查一次，还在就 `unset`，直到清干净。

## 理由

宿主那个开关能做到整个插件不加载；插件那个只是让代码在位却不干活——对用户没有额外价值，却多一份要维护、要解释的状态。同一个问题有两个家时，用户无法判断该动哪一个。

## 被否决的备选

- **保留两个开关、只改文案**：用户实测指出这是重复的（宿主已经有启停），而且两个都叫"开/关"的勾选摆在一起无法解释差别。
- **隐藏 `enabled` 但保留它的判断**：看不见的开关比看得见的更糟——用户会以为插件关不掉，实际是某个看不见的字段在挡。
- **让 `enabled` 直接改名为"允许 Agent 生图"的语义（删掉 `allowAgentGeneration`）**：文档里的 `enabled: false` 会变成"Agent 不能生图"，名与实不符；而且 `enabled` 在 DSH 的插件配置语境里另有含义（宿主启停），同名两义必然误读。
- **保留 `enabled` 作为别名（读到 `false` 就当作不允许 Agent 生图）**：等于让一个退役键继续决定行为，而用户在界面上再也看不到它——行为会由一份看不见的旧配置决定。

## 后果

- **文档里存着 `enabled: false` 时，插件是启用的。** 要停用请用宿主的插件管理，那也是唯一能真正不加载它的地方。
- 生成路由与 Agent 工具不再回 `plugin-disabled`；`agent-generation-disabled` 仍在，对应"允许 Agent 生图"关掉。
- 随包技能随插件加载而注册，与任何设置无关；`announceToAgent` 只管提示词预算（Agent 可见面的承载分工归 ADR-0001）。
- 宿主若严格校验设置文档，未知键可能在入站路上就被丢掉，此时没有东西可清：清理是"还在就清掉"，不是"必须清到"。
