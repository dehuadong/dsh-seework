# 文档归属与标准（dsh-seework 插件工程）

本文件是本工程**文档的统一入口**：先判定工件属于哪一类、由谁拥有，再按该属主的规则创建与维护。本目录既是工程根也是本项目的仓库管理根，下面的相对链接以本文件所在位置（`docs/AGENTS.md`）为基准。

## 文档类型与属主

| 工件 | 位置 | 拥有什么 | 不承载什么 |
| --- | --- | --- | --- |
| 工程说明与使用指南 | [`../README.md`](../README.md) | 项目入口、安装与使用方式、进一步阅读路径 | 行为合同与设计正文 |
| 架构与实现**地图** | [`architecture.md`](architecture.md) | 每处行为的现状与简短的「为什么」 | 长文取舍、评审结论、工作进度 |
| 详细设计 | [`design/`](design/) | 技术方案、关键约束、真实取舍、迁移与验证影响；**一个主题一份** | 产品范围与交付进度 |
| 架构决定（ADR） | [`adr/`](adr/) | 不可逆、值得留档的取舍与理由（含被否决的备选） | 完整合同与实现状态 |
| GUI 端到端核对 | [`gui-verification.md`](gui-verification.md) | 怎么核、断言什么、哪些零成本、哪些要备份还原 | 行为合同本身 |
| 领域术语表 | [`../CONTEXT.md`](../CONTEXT.md) | 领域语言与用词边界 | 代码、字段与调用方式 |
| Agent 变更与决策记录 | [`../.agents/notes/`](../.agents/notes/README.md) | 本次变更独有的决定理由、后果与验证证据 | 其它属主已拥有的合同或决定正文 |
| 提案与工作项 | GitHub Issues | 交付范围、工作状态、评审与批准事实、工件链接 | 仓库内的合同或设计正文 |
| 代理入口与插件细则 | [`../AGENTS.md`](../AGENTS.md) | 文档归属指针、边界纪律、验证入口、GUI 核对入口 | 上面各属主的正文 |

不存在的位置不要为了凑齐表格而新建；研究、验证清单与外部参考资料按需建立，不构成默认文档层。

说明：`architecture.md`、`gui-verification.md`为历史开发文档，后期新开发不再记录，如需要另外建档

## 状态头与修订

设计与 ADR 文档头部登记状态，取值 `草稿 → 已评审通过（日期）→ 实现完成（提交）→ 已取代（链接）`；设计与 ADR 各自的附加字段沿用文件既有写法。

- **追加内容 = 进入新修订**：先把状态退回 `草稿`，评审通过后再写日期；不得在「已评审通过」的状态下继续长内容。
- **已实现 / 已取代**：只加**失效范围注记与链接**，不删不改正文。
- **状态不是批准**：它是登记下来的约定，**不从文件内容反推批准**；批准与执行授权另行判断。

## 一个事实一个家

每个事实由拥有它的文档层完整说明，其它位置用链接指过去：行为合同归架构地图与详细设计，难以逆转的架构选择归 ADR，一次变更独有的理由与验证归 Agent Note，工作范围与进度归 Issue，领域用词归 `CONTEXT.md`。

- 一份文档只对自己的主题写全，不把其它主题的清单抄进来。
- 机器能生成或校验的清单（工具参数表、路由表、测试清单）不手抄，指向源码或产物。
- 写文档先确定归属与位置，再决定本层的细节程度；不属于本层的内容搬回属主，原地留链接。

## 写作与审阅

- **写当前状态**：变更过程归提交与 Agent Note，正文只写仍生效的内容。
- **保留完整命题**：删形容词、重复与叙述之前，确认事实仍完整，包括执行者、动作、条件、时序、义务强度、例外、失败方式与后果。
- **注释写完整合同，不写推理记录**：保留行为、失败、时机、所有权、义务与不显然的用法；理由链接到设计或 ADR，不写在相邻处重复。
- **事实与推论分开**：可核实的事实标明证据位置（用例名、命令、提交、留档路径）；推论、估计与待确认事项明确标注，不写成既成事实。
- **不写状态标注**：避免「已实现」「未来会……」这类会随交付腐坏的文字，状态由跟踪器、目录与代码表达。
- 加粗只用于改变行为的句子或真正重要的对比。
- 审阅时先界定范围，再逐项判断保留、补写、删减或移走；先把事实放回属主，再更新派生引用。

## 文件边界与外部属主

- 本工程文档**只**写入本目录的 `docs/`、`README.md` 与 `CONTEXT.md`。
- 本工程**调用** SeeAI Hub 的对外接口，不定义它们：对外契约（图片、目录、错误、账务）的属主是 SeeAI Hub 仓库（`dehuadong/seeaihub`）的 `docs/api/`，**不在本目录**；契约变更以那边为准，插件侧只做适配。
- 不复制外部属主的正文，用仓库名加路径指明来源。
- 本工程与 SeeAI Hub 仓库的 `dsh-seework/` 同源；那边保留既有提交历史与其它工程的开发文档，本目录不镜像它们。

## 更新责任

改动方在同一个变更里维护本表：新增工件类别或改变归属时更新对应行；本工程的细则只在 [`../AGENTS.md`](../AGENTS.md) 登记，本文件只登记位置与衔接。注册与记录**不新增**评审、批准或执行权限。
